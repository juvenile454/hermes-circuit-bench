# Desktop fixtures

One example response per backend route, each a result envelope. The desktop UI builds against these without a
backend; they are real responses (`tests/test_api_fixtures.py` compares them with the routes).
`tests-js/test_fixtures.mjs` checks the required envelope fields.

Data are synthetic (demo project `laser-trigger`, MAC `aa:bb:cc:dd:ee:ff`, paths `/home/user/…`).

`flash.check.{ok,flash_disabled,chip_mismatch}.json` (`GET /board/flash/check`) are real answers for three
states of `laser-trigger`; `tests/test_h_ui_flash_fixtures.py` generates and compares them
(`.venv/bin/python tests/test_h_ui_flash_fixtures.py --regen "$TMPDIR/cb-flash-check"`, then copy the three files here).
`lib/fixtures.js` picks one by the request (real port → `flash_disabled`, project chip ≠ detected chip → `chip_mismatch`).

Module fixtures (generated by `tests/test_api_fixtures.py --regen`, regenerated when the catalog changes):
`modules.list`, `modules.info.<id>` (ids in `MODULE_INFO_FIXTURES`), `project.modules-demo` and
`pins.check.modules-demo` (the project in `MODULES_DEMO`), `calc.meta` (`GET /calc`).
